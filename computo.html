03

Jellyfin: GPU y memoria dedicadas

Con la biblioteca creciendo, transcodificar por software empezaba a saturar la CPU del host. Para evitarlo se pasó la iGPU (Quick Sync) del host por PCI passthrough directamente a la VM, y se fijó la RAM de esa VM para que un pico de transcodificación no compita por memoria con el resto del clúster.

Passthrough de la iGPU

El host que aloja la VM reserva su iGPU en exclusiva vía PCI passthrough (DirectPath I/O): el hypervisor deja de gestionarla y el control pasa por completo a la VM. Dentro de Ubuntu el dispositivo aparece como /dev/dri; se dio permiso al usuario del contenedor (grupo render/video) para que Jellyfin use Quick Sync (VAAPI) sin correr como root. Contrapartida: mientras la iGPU esté pasada por passthrough, esa VM concreta pierde vMotion/DRS y queda anclada a ese host — el resto del clúster sigue con HA normal.

Memoria fijada

En vSphere se igualaron reservation y limit de RAM para la VM: le garantiza memoria mínima disponible siempre (sin swap ni contención con otras VMs) y evita que un pico de transcodificación le quite RAM al resto del clúster. Separa a Jellyfin del pool de memoria compartido, a cambio de reservar esa RAM de forma fija aunque la VM esté inactiva.

04

Acceso remoto

Jellyfin se publica hacia fuera con un túnel de Cloudflare: sin abrir un solo puerto en el router MikroTik. El dominio se gestiona con el DNS de Cloudflare, que además actúa como capa de proxy inverso frente al contenedor.
